# C1.2 BFCL Execution Plan

## Objective

Construct a C1.2 BFCL-derived device-enum drift package using
`VehicleControlAPI.startEngine` from `multi_turn_base_95`.

C1.2 tests declaration-only recovery from a private enum remap:

```text
semantic goal: start the engine
r- executable token: START
r+ executable token: X7
```

The natural-language user goal, function name, argument name, safety
preconditions, and final device outcome remain unchanged.

## Drift Definition

The physical drift is an abrupt private enum remap:

```text
operator: enum_remap + enum_deprecate
changed obligation: E01 start_engine
old token: START
new token: X7
old token status in r+: deprecated_invalid
```

Unchanged obligations include stop-engine, headlights, climate, door locking,
parking brake, and status-display mappings.

## Evidence Allocation

C1.2 is a D1-only condition:

```text
D1 = 100%
D2 = 0%
D3 = 0%
```

The learner-visible evidence is only:

```text
evidence/d1_changelog.md
```

Do not provide:

```text
D2 demonstrations
D3 probe outcomes
replacement-leaking runtime hints
skill_r_plus_oracle.md
```

The expected learner update is:

```diff
- startEngine(ignitionMode="START")
+ startEngine(ignitionMode="X7")
```

## Sibling Construction

Use 19 siblings with C1.1-style task IDs:

```text
C1.2_aff_001..C1.2_aff_008
C1.2_ret_001..C1.2_ret_005
C1.2_open_001..C1.2_open_004
C1.2_null_001..C1.2_null_002
```

The expected composition is:

```text
affected: 8
unchanged-retention: 5
boundary/open-set: 4
matched-null: 2
```

Affected siblings require `E01`. Retention siblings exercise unchanged vehicle
operations. Boundary/open-set siblings have empty executable gold calls.
Matched-null siblings use `r_null`, where surface wording changes but the
physical mapping remains `START`.

## Compilation

Regenerate package-level answers and the repository gold mirror with:

```bash
python data/C_drift_benchmark/C1.2/device_enum/compile_c1_3.py --write
```

This writes:

```text
possible_answer_r_minus.json
possible_answer_r_plus.json
../gold_answer/C1.2.json
```

## Validation

Run:

```bash
python data/C_drift_benchmark/C1.2/device_enum/validation/replay_checks.py
```

Validation checks:

- manifest shape and C1.1-style ID naming;
- prompt and learner-visible doc non-leakage;
- D1 changelog completeness;
- r- and r+ answer replay;
- stale r- affected calls fail under r+ with `Invalid ignition mode.`;
- boundary/open-set and matched-null controls.

Empirical metrics such as RR, IAR, collateral damage, recovery latency, and
identification budget are intentionally unset until real benchmark runs are
executed.
