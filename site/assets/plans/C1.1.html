C1.1 — BFCL Device-Enum Codebook Drift: Execution Plan

0. Goal and roster contract

Build an executable BFCL-derived **C1.1** task family.

**Roster contract**

  • Family: `device-enum codebook`
  • Origin: BFCL pattern
  • Skill store: versioned enum table, action schema, execution templates
  • Application recipe: semantic intent → current private enum → validated call
  • Drift: `enum_remap + enum_deprecate`
  • Topology: replacement / retirement
  • Schedule: abrupt
  • Changed-mass target: approximately **25% of performance-relevant enum obligations**, with **one old value explicitly deprecated**
  • Invariant: natural-language intents and device outcomes remain fixed
  • Stale failure: old skill invokes a wrong state or invalid enum
  • Evidence:
  • D1 = 0%
  • D2 = 50% successful transcripts
  • D3 = 50% safe probes
  • Required update: patch enum rows, version-bind templates, replay affected states
  • Validation: entry recovery, invalid-action rate, state replay, probe count
  • Readouts: entry RR, IAR, `d*`, CD

The cleanest BFCL substrate is `VehicleControlAPI`, whose current executable backend and tool docs already contain enum-bearing actions such as engine ignition, headlights, parking brake, and climate mode.

3. Select the exact physical drift

Use three changed obligations.

Recommended pilot:

E01: start_engine
START → X7

E02: headlights_auto
auto → H2

E03: climate_defrost
defrost → C9

Explicitly tombstone one old value:

deprecated token: defrost

That means in `r+`:

adjustClimateControl(mode="defrost")

must return an invalid/deprecated-mode error rather than acting as an alias for `C9`.

Keep the semantic effects unchanged:

X7 → engine running
H2 → automatic headlight behavior
C9 → defrost climate behavior

Create:

drift_benchmark/C1.1/device_enum/drift_spec.json

Example:

{
  "operator": ["enum_remap", "enum_deprecate"],
  "schedule": "abrupt",
  "topology": ["replacement", "retirement"],
  "changed_mass": 0.25,
  "changes": [
    {
      "obligation": "E01",
      "old": "START",
      "new": "X7",
      "deprecated_old": false
    },
    {
      "obligation": "E02",
      "old": "auto",
      "new": "H2",
      "deprecated_old": false
    },
    {
      "obligation": "E03",
      "old": "defrost",
      "new": "C9",
      "deprecated_old": true
    }
  ]
}

If C1.2 has already been built, reuse the same physical `r- → r+` event for shared obligations whenever possible. C1.1 and C1.2 should differ in evidence, not unnecessarily in the drift itself.

4. Hide the private enum mapping from the task-level tool docs

The original BFCL docs leak values such as:

[Enum]: ["START", "STOP"]

For this drift family, the current token mapping must live in the persistent skill or be acquired from evidence.

Create version-neutral docs:

drift_benchmark/C1.1/device_enum/vehicle_control_private_doc.json

For changed parameters, replace explicit enum listings with wording such as:

"The private ignition token used by the current vehicle-control interface."

Similarly:

"The private token for the requested headlight mode."
"The private token for the requested climate mode."

Keep function names and parameter names unchanged.

Do not expose `X7`, `H2`, or `C9` in normal task documentation.

5. Build executable regime `r-`

Create:

drift_benchmark/C1.1/device_enum/vehicle_control_r_minus.py

Use the original BFCL behavior.

Relevant examples:

if ignitionMode == "START":
    self.engine_state = "running"
if mode == "auto":
    # original automatic headlight behavior
self.acMode = mode  # defrost is valid under r-

Create:

regime_r_minus.json

containing the exact semantic-to-token map.

---

6. Build executable regime `r+`

Copy `vehicle_control_r_minus.py` to:

vehicle_control_r_plus.py

Modify only the selected private semantics.

Example:

if ignitionMode == "X7":
    self.engine_state = "running"

For headlights, replace the current executable `auto` token with `H2`.

For climate defrost:

if mode == "defrost":
    return {"error": "Deprecated climate mode."}

and make:

mode == "C9"

execute the same semantic defrost behavior.

Do not change unrelated vehicle behavior.

11. Construct D3 safe probes for the remaining 50%

Create:

evidence/d3_probe_interface.py
evidence/d3_probe_log.jsonl

Allow only a bounded safe probe surface.

Example probe:

probe("setHeadlights", {"mode": "auto"})

might return:

{"error": "Invalid headlight mode."}

Probe:

probe("setHeadlights", {"mode": "H2"})

returns the correct automatic-light outcome.

For the deprecated climate token:

probe("adjustClimateControl", {"temperature": 20, "mode": "defrost"})

returns:

{"error": "Deprecated climate mode."}

and:

probe("adjustClimateControl", {"temperature": 20, "mode": "C9"})

returns the semantic defrost state.

Every probe must:

  • be safe;
  • be metered;
  • record action and outcome;
  • not leak held-out evaluation tasks.

16. Validation checks

Entry recovery

Check whether each changed semantic intent maps to the correct current token.

Invalid-action rate (IAR)

invalid enum calls / total executable calls

State replay

Execute the candidate updated call and verify final simulator state.

Probe count / `d*`

Count metered D3 probes required to identify the missing mappings.

Collateral damage (CD)

On unchanged enum obligations:

updated skill should produce the same calls/outcomes as S-

Boundary/open-set

Unsupported semantic requests should abstain rather than guess a private token.

---

17. Acceptance checklist

The C1.1 pilot is construction-ready only if:

  • [ ] user prompts do not reveal private tokens;
  • [ ] normal function docs do not reveal current changed tokens;
  • [ ] `r-` and `r+` preserve semantic device outcomes;
  • [ ] approximately 25% of selected enum obligations are changed;
  • [ ] one old token is explicitly tombstoned;
  • [ ] D2 covers 50% of changed obligation weight;
  • [ ] D3 covers the remaining 50%;
  • [ ] no D1 evidence is exposed;
  • [ ] stale skill fails or incurs invalid actions on affected siblings;
  • [ ] oracle skill succeeds;
  • [ ] updated skill is replay-validated;
  • [ ] unchanged siblings show negligible collateral edits.
