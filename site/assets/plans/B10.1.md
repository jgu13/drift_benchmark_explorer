# B10.1 Account-Actions Execution Plan

## Objective

Build a tau2-bench-pattern account-actions drift benchmark aligned with
`Drift_benchmark_architecture_guide.md`.

The benchmark models one compact fictional account-service domain. The drift is:

```text
Drift: cap_shift + precondition_add
Topology: replacement + expansion
Schedule: abrupt

D1 = 50%
D2 = 0%
D3 = 50%
```

The stale learner skill jointly stores semantic policy rules, action
preconditions, and exception order. The current regime changes exactly two
atomic obligations:

```text
E01: issue_account_credit amount cap changes from 100 to 60.
E02: verify_identity is required before issue_account_credit.
```

No exception rule is added in B10.1.

## Drift Definition

Primary action:

```text
issue_account_credit(amount, reason)
```

Supporting action:

```text
verify_identity()
```

Unrelated controls:

```text
update_email()
set_notification_preference()
view_account()
reset_password()
```

`r_minus` semantics:

```text
credit cap = 100
identity verification is not required before issue_account_credit
```

`r_plus` semantics:

```text
credit cap = 60
identity verification is required before issue_account_credit
```

State includes:

```text
identity_verified
credit_total_this_episode
account_status
email
notification_preference
password_reset_required
audit_log
```

The `r_plus` backend must reject `issue_account_credit(...)` when identity is
unverified. Both regimes reject credits above the active cap. A plan that
reaches a requested end state by violating the cap or precondition fails.

## Evidence Allocation

Learner-visible evidence is limited to `account_actions/evidence/`.

D1 contains exactly one complete atomic artifact for E01:

```text
evidence/d1_rule_credit_cap.md
```

It reveals the current 60-unit cap and the previous 100-unit cap. It does not
mention the identity prerequisite.

D2 is intentionally absent:

```text
D2 = 0%
```

D3 contains only the metered current-regime probe log for E02:

```text
evidence/d3_probe_interface.py
evidence/d3_probe_log.jsonl
```

The D3 probe is safe, metered, current-regime, evidence-only, and disjoint from
evaluation siblings. The smallest discriminating sequence is:

```text
identity_verified = false
issue_account_credit(40, "goodwill") -> rejected: identity verification required
verify_identity() -> success
issue_account_credit(40, "goodwill") -> success
```

`skill_r_minus.md` is learner-visible as the stale skill. `skill_r_plus_oracle.md`
is hidden and is only for evaluation and validation.

## Sibling Construction

Build exactly 19 evaluation siblings:

```text
8 affected
4 unchanged-retention
4 boundary/open-set
3 matched-null
= 19 total
```

Use stable hyphenated IDs:

```text
B10.1-aff-001 ... B10.1-aff-008
B10.1-ret-001 ... B10.1-ret-004
B10.1-bnd-001 ... B10.1-bnd-004
B10.1-null-001 ... B10.1-null-003
```

Every sibling is compiled against both `r_minus` and `r_plus`. A sibling is
affected from executable obligation support, not wording:

```python
affected = (
    gold_or_optimal_trace_intersects_changed_obligation
    or graded_final_output_differs
    or current optimal-cost target changes
)
```

Affected siblings cover cap-only, precondition-only, combined cap and
precondition, compound workflows, and stale-skill traps. At least two affected
siblings require both repaired components.

Unchanged-retention siblings cover `update_email`,
`set_notification_preference`, `view_account`, and `reset_password` with no
credit action.

Boundary/open-set siblings cover amount exactly 60, amount just above 60,
identity already verified, and malformed/unsupported credit requests.

Matched-null siblings use paraphrase or irrelevant metadata changes that
preserve the same required end state and do not introduce persistent rule edits.

## Compilation

The package compile script is:

```bash
python data/B10.1/account_actions/compile_b10_1.py --write
```

It loads `siblings.json`, derives task answers from
`r_minus_ground_truth` and `r_plus_ground_truth`, and writes:

```text
possible_answer_r_minus.json
possible_answer_r_plus.json
sibling_summary.json
```

No repository-level gold mirror is required for this B-family package.

## Validation

Run:

```bash
python -m json.tool data/B10.1/account_actions/siblings.json >/dev/null
python data/B10.1/account_actions/compile_b10_1.py --write
python data/B10.1/account_actions/validation/replay_checks.py
bash data/B10.1/account_actions/validation/validate_b10_1_architecture.sh
```

Validation checks:

- exact 19 total siblings with 8/4/4/3 slice counts;
- canonical `siblings.json` manifest shape with a `tasks` array;
- package-level `possible_answer_r_minus.json` and
  `possible_answer_r_plus.json`;
- D1/D2/D3 evidence allocation of 50/0/50;
- D1 file starts with `d1` and reveals only the cap rule;
- D3 file names start with `d3` and probes only the identity precondition;
- no D2 evidence files;
- local regime files and local replay validation exist;
- oracle answers replay successfully against local backends;
- unchanged-retention siblings do not use changed obligations;
- construction report leaves unmeasured empirical metrics as `null`.

## Limitations

This pilot is deliberately small. It is intended to validate architecture,
coverage, leakage boundaries, oracle replay, stale-skill gaps, and collateral
damage behavior before scaling.

Empirical metrics such as zero-shot success, stale-skill gap magnitude,
adaptation lift, and collateral damage rate are not measured by construction.
They must remain `null` until an experiment is run.
