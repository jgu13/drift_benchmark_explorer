C3.1 — BFCL CLI-Semantics Drift: Execution Plan

0. Goal and roster contract

Build an executable BFCL-derived **C3.1** family for CLI semantics.

**Roster contract**

  • Family: `CLI semantics`
  • Origin: BFCL v4 pattern
  • Skill store: versioned command grammar, flag semantics, compatibility constraints, recipes
  • Application recipe: select current command form, execute, verify output before reuse
  • Drift: `flag_remap + deprecate + shortcut_add`
  • Topology: replacement / retirement / improvement
  • Schedule: abrupt
  • Changed-mass target: **two flags plus one new shortcut**
  • Invariant: target output remains fixed; command route/cost may change
  • Stale failure:
  • old recipe may fail;
  • repaired conservative recipe may remain correct but suboptimal
  • Evidence:
  • D1 = 50% changelog
  • D2 = 0%
  • D3 = 50% help text + probes
  • Required update: repair tool model and recipes; promote only after output/cost validation
  • Validation: IAR, output correctness, RR/CRR, probes, BE
  • Readouts: IAR, RR, CRR, `d*`, BE

BFCL's `GorillaFileSystem` already provides command-like operations (`find`, `cp`, `mv`, `cat`, `wc`, etc.). However, native BFCL exposes them as structured Python-style functions rather than a true command grammar. To make C3.1 genuinely about **CLI flag semantics**, create a thin BFCL-compatible CLI adapter over `GorillaFileSystem`.

2. Keep `GorillaFileSystem` as the execution backend

Do not reimplement filesystem semantics.

Reuse:

bfcl_eval/eval_checker/multi_turn_eval/func_source_code/gorilla_file_system.py

as the underlying stateful filesystem.

The new CLI layer should translate a command string into calls on this existing backend.

This preserves BFCL state transitions and evaluation behavior.

---

3. Add a new BFCL backend class: `GorillaCLI`

Create:

bfcl_eval/eval_checker/multi_turn_eval/func_source_code/gorilla_cli.py

Expose one primary function:

run(command: str) -> dict

Internally:

  1. tokenize the command string;
  2. parse it according to the active CLI regime;
  3. translate it into one or more `GorillaFileSystem` operations;
  4. execute them;
  5. return stdout/error/exit-code metadata.

Suggested response:

{
  "stdout": "...",
  "stderr": "",
  "exit_code": 0,
  "operations": 1
}

Do not expose the full private grammar in the standard function schema.

6. Define the `r-` command grammar

Create:

grammar_r_minus.json

Use a small grammar sufficient for the selected tasks.

Example:

find --path <directory> --name <name>
cat <file>
cp <source> <destination>
mv <source> <destination>
wc -l <file>
sort <file>

For `multi_turn_base_19`, the baseline route may be:

find --path . --name test_document.txt
cp test_document.txt archives
cd archives
mv test_document.txt final_document.txt
cat final_document.txt

You may instead keep BFCL's current-directory restrictions and model `cd` explicitly.

Define operation cost as the number of underlying filesystem operations, not merely the number of high-level tool calls.

---

7. Define the exact C3.1 physical drift

The roster calls for:

two flags plus one new shortcut

Use:

Flag remap

find --path <dir>

becomes:

find --root <dir>

Old `--path` is invalid in `r+`.

Flag deprecation

wc -l <file>

is retired.

The new valid form is:

wc --lines <file>

`-l` must return a deprecation/invalid-option error in `r+`.

Shortcut addition

Add a new command:

copy-as <source> --to <directory> --name <new_name>

This performs the same semantic operation as:

cp + cd/mv

but at lower cost.

Example:

copy-as test_document.txt --to archives --name final_document.txt

The final filesystem state is identical to the old multi-command route.

Create:

drift_spec.json

with:

{
  "operator": ["flag_remap", "deprecate", "shortcut_add"],
  "schedule": "abrupt",
  "changes": [
    {
      "command": "find",
      "old_flag": "--path",
      "new_flag": "--root",
      "type": "remap"
    },
    {
      "command": "wc",
      "old_flag": "-l",
      "new_flag": "--lines",
      "type": "deprecate"
    },
    {
      "command": "copy-as",
      "type": "shortcut_add",
      "replaces_route": ["cp", "mv"]
    }
  ]
}

8. Implement the `r-` parser

Create:

gorilla_cli_r_minus.py

Supported examples:

find --path . --name test_document.txt
wc -l summary.txt
cp source destination
mv source destination
cat file
sort file

Translate into existing BFCL filesystem methods.

Example:

find --path . --name x

maps to:

filesystem.find(path=".", name="x")

---

9. Implement the `r+` parser

Create:

gorilla_cli_r_plus.py

Rules:

--path    → error
--root    → valid

-l        → deprecated/error
--lines   → valid

copy-as   → valid and lower-cost

Implement `copy-as` by executing the underlying `cp` and `mv`/rename logic internally, but charge it as a deliberately cheaper route according to the benchmark cost model.

Keep the final filesystem state exactly equivalent.

---

10. Define the cost model explicitly

Because C3.1 includes an improvement operator, the cost model must distinguish:

old correct route
new shortcut route

Recommended cost:

each underlying primitive filesystem operation = 1
help query = 1
invalid probe = 1
copy-as shortcut = 1

Thus:

r- copy + rename:
cp + mv = 2

r+ copy-as:
copy-as = 1

Record both:

semantic correctness
execution cost

Never score only the number of LLM tool-call messages if the wrapper expands one command internally.

---

11. Hide current grammar from ordinary task prompts

Convert BFCL source prompts to semantic instructions.

For example:

"Find test_document.txt, copy it into archives as final_document.txt,
then show me its contents."

Do not write:

--path
--root
-l
--lines
copy-as

in the user request.

The persistent skill stores the CLI grammar.

`find --root <directory> --name <name>`

`copy-as <source> --to <directory> --name <new_name>`

For each candidate new recipe:

  2. verify the final filesystem/output;
  3. measure cost;
  4. only then write it into persistent skill.

21. Metrics

IAR

Invalid command/flag actions divided by executable attempts.

RR

Correctness recovery for syntax changes that otherwise cause failure.

CRR

Cost recovery for the new shortcut at matched final output.

`d*`

Minimum help/probe budget needed to identify current grammar sufficiently.

BE

Break-even horizon:

future saved command cost
>
one-time discovery/update cost

Do not claim BE until repeated post-drift siblings exist.

23. Acceptance checklist

  • [ ] underlying filesystem semantics are still BFCL `GorillaFileSystem`;
  • [ ] CLI adapter is executable and stateful;
  • [ ] user prompts state semantic goals, not current flags;
  • [ ] normal function docs do not leak the private grammar;
  • [ ] exactly two flag changes are implemented;
  • [ ] one old flag is explicitly deprecated;
  • [ ] one semantically equivalent faster command is added;
  • [ ] final output/filesystem state remains invariant;
  • [ ] D1 localizes changed commands but leaves exact syntax unresolved;
  • [ ] D3 help/probes reveal exact syntax and cost;
  • [ ] D2 is withheld;
  • [ ] stale skill exhibits both failure and suboptimal-but-correct cases;
  • [ ] candidate updates are execution-validated before storage;
  • [ ] unchanged commands show negligible collateral edits.
