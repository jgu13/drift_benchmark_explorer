C1.2 BFCL Execution Plan

Objective

Construct a C1.2 BFCL-derived device-enum drift package using `VehicleControlAPI.startEngine` from `multi_turn_base_95`.

C1.2 tests declaration-only recovery from a private enum remap:

semantic goal: start the engine
r- executable token: START
r+ executable token: X7

The natural-language user goal, function name, argument name, safety preconditions, and final device outcome remain unchanged.

Drift Definition

The physical drift is an abrupt private enum remap:

operator: enum_remap + enum_deprecate
changed obligation: E01 start_engine
old token: START
new token: X7
old token status in r+: deprecated_invalid

Unchanged obligations include stop-engine, headlights, climate, door locking, parking brake, and status-display mappings.

Validation

Run:

python data/C_drift_benchmark/C1.2/device_enum/validation/replay_checks.py

Validation checks:

  • manifest shape and C1.1-style ID naming;
  • prompt and learner-visible doc non-leakage;
  • D1 changelog completeness;
  • r- and r+ answer replay;
  • stale r- affected calls fail under r+ with `Invalid ignition mode.`;
  • boundary/open-set and matched-null controls.

Empirical metrics such as RR, IAR, collateral damage, recovery latency, and identification budget are intentionally unset until real benchmark runs are executed.
